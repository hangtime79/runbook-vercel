## What
The Change control card on `/governance`: the required checks, and the workflow file that defines them. This is the first of three stops on this card (18, 20 and 21).

## Tell
The APRA moment. Say the quote, then show a change.


## On Vercel
Every branch and pull request gets its own preview deployment, and v0 opens a working branch per chat with a pull request for review. Vercel Agent can review the code (public beta). For the bank: the APRA change-control concern is answered by one flow, whoever or whatever wrote the change. *On the other side of the bridge: the pull request and its Vercel preview comment. Source: governance-research.md §5.*

## Say
APRA's letter to industry in April said it directly: *the volume and speed of AI assisted software development is placing strain on the effectiveness of change and release management controls.* Here's what a change looks like on this platform, whether an investigator, a coding agent or v0 made it.

v0 works the same way for your non-developers: a working branch per chat, a pull request for review.

## CIO
Change and release controls, applied the same way to a change from an investigator, a coding agent or v0.

## Leave the app
Show a pull request (prepared beforehand, or push live): a copy change or a new chapter, authored by a coding agent.

## Craft
Open the act with the regulator's own words, then show the mechanism that answers them.
